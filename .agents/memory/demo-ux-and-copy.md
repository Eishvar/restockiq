---
name: Demo UX and copy
description: Product context and user-directed copy constraints for the hackathon demo.
---
The app is being prepared for a hackathon judging demo. Restricted screens should let judges switch to a permitted demo identity rather than reaching a dead end; permission checks themselves must remain intact.

**Why:** The user wants judges to be able to experience the owner, manager, and staff paths without mistaking an intentionally restricted screen for an unfinished product.

**How to apply:** Keep demo identity switching explicit, choose existing users with the required role, and refresh data under that identity. Never simply hide or bypass role restrictions to reveal a page.

Do not add explicit claims about time saved, minutes to complete a plan, or comparisons with doing work by hand.

**Why:** The user explicitly requested “Show, Don't Tell”: efficiency should be visible through the interaction, not through boastful marketing copy.

**How to apply:** Use short, plain-English labels, real data, and clear actions; avoid reintroducing time-saved claims during dashboard or demo polish.

The app's colour scheme should follow Orbyte's official website, https://www.orbyte.my/.

**Why:** The user explicitly requested matching Orbyte's colours, rather than retaining the original green branding.

**How to apply:** Keep future decorative accents consistent with the shared Orbyte-derived palette while retaining distinct semantic success, warning, and error colours. This is a colour alignment, not a request to rename RestockAI or copy Orbyte's content.
